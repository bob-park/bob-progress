# 단계별 캐릭터와 에이전트 캐릭터: 설계 (project)

## 의도

⚡ SUPERPOWERS 타임라인은 지금 `⠹ execute ███▓▓░░ 3/7` 같은 글자로만 진행을 보여 준다.
[savvy-progress](https://github.com/JohnnyVizz/claude-kit/tree/main/plugins/savvy-progress)에서는 픽셀 게(Clawd)가 일하는 동안 움직인다. 이 플러그인도 그렇게 만들어서 지금 무슨 일을 하는지 한눈에 보이고 보는 재미도 있게 한다.
사용자는 다음을 원한다.
- 단계마다 서로 다른 캐릭터를 쓴다.
- 에이전트는 단계와 또 다른 캐릭터로 그린다.
- 데스크톱 앱과 터미널 **둘 다**에서 움직인다.

승인된 목업은 `docs/superpowers/specs/2026-11-02-stage-characters-mockup.html`이다. 브라우저로 열면 움직이는 모습을 볼 수 있다. 이 문서는 목업과 함께 읽는다. 모양(픽셀 격자, 문자 프레임, 색)은 목업의 정의를 정답으로 본다.

## 목표

- **현재 단계 카드**: 진행 중인 단계 줄이 카드로 커진다.
  - 왼쪽에 그 단계의 캐릭터를 그린다.
  - 오른쪽에는 지금 줄의 내용을 그대로 둔다. 단계 이름·시간, execute면 plan 막대 `3/7`과 현재 task, 그 밖의 단계면 캐릭터 이름(예: `건설공`)이 들어간다.
- **단계 캐릭터 7종**: 모두 Clawd 몸통 하나를 같이 쓰고, 모자와 도구만 다르다.

  | 단계 | 캐릭터 | 모자 | 움직임 |
  |---|---|---|---|
  | brainstorm | 생각쟁이 | 없음 | 생각 거품 3개가 차례로 깜빡인다 |
  | spec | 서기 | 깃털 | 종이에 줄이 하나씩 생기고 깃펜이 까딱인다 |
  | plan | 설계사 | 보라 베레모 | 청사진 위에서 연필이 움직인다 |
  | worktree | 정원사 | 밀짚모자 | 화분의 새싹이 자란다 |
  | execute | 건설공 | 노란 안전모 | 망치를 휘두르고 불꽃이 튄다 |
  | review | 탐정 | 체크무늬 사냥모자 | 돋보기가 좌우로 훑는다 |
  | finish | 축하꾼 | 고깔모자 | 체커 깃발이 펄럭이고 색종이가 깜빡인다 |

  모든 단계에서 다리를 번갈아 들고 몸이 1px씩 오르내린다.
- **에이전트 캐릭터 "비트"**: Clawd와 다르게 생긴 작은 로봇이다. 안테나가 있다.
  - 역할마다 몸 색과 도구가 다르다.
    - `impl`: 파랑, 렌치
    - `review`/`re-review`: 노랑, 돋보기
    - `fix`: 빨강, +
    - 역할이 없는 일반 에이전트(AGENTS 섹션): 초록, 도구 없음
  - 일하는 동안에는 깡충거리고 안테나가 깜빡인다.
  - 비트는 에이전트 줄 맨 앞의 상태 아이콘(`⠹`/`⏸`/`✓`/`✗`/`⚠`)을 **대신한다**. 실패와 리뷰 지적은 표정과 색으로 구분해서, 실패한 에이전트가 웃는 얼굴로 보이지 않게 한다(내 판단).

    | 상태 | 터미널 | 데스크톱 |
    |---|---|---|
    | running | `[•_•]⚙` ↔ `[•_•]✲` (역할 도구) | 깡충거림, 안테나 깜빡임 |
    | waiting | `[-_-]z` 멈춤 | 멈춤, 눈 감음 |
    | done | `[^_^]✓` 초록 | 멈춤, 초록 체크 |
    | failed | `[x_x]✗` 빨강 | 멈춤, 빨간 X |
    | verdict `issues` | `[o_o]⚠` 노랑 | 멈춤, 노란 ⚠ |
- **끝난 단계의 에이전트**: 지금처럼 그 단계 아래에 남긴다. `rolesOf`의 정렬과 `ROLES_SHOWN = 5`, `… N more`를 그대로 따르고, 상태 아이콘 자리에 멈춘 비트를 그린다(사용자 결정).
  - 목업은 현재 단계 카드 아래에만 에이전트를 그렸지만, 이 부분은 목업을 따르지 않는다.
  - 데스크톱: 끝난 단계 줄(1배 캐릭터 + `✓ stage 04:10`) 아래에 비트 줄이 들여쓰기되어 붙는다.
- **움직임 조건**:
  - 단계 캐릭터는 지금 `busy`(`derive().busy`)일 때만 움직인다. idle이면 첫 프레임에 멈춘다.
  - 비트는 그 에이전트가 `running`일 때만 움직인다. `waiting`이면 멈춘다.
- **화면별 표현**:
  - 데스크톱(`e.surface === 'desktop'`, 그 밖의 `Svg`가 있는 surface 포함)
    - SVG 픽셀 스프라이트를 쓰고 CSS keyframes로 움직인다.
    - 현재 단계 카드는 4배, 비트는 2배로 그린다.
    - 끝난 단계 줄 앞에는 1배 크기의 멈춘 캐릭터가 붙는다.
  - 터미널
    - 목업의 문자 캐릭터를 그린다. 모자 줄 1줄과 `▐▛███▜▌`·`▝▜█████▛▘`·발 줄로 4줄이고, 오른쪽에 3칸짜리 도구 열이 붙는다.
    - 프레임은 기존 `FRAME_MS` 시계에 맞춰 바꾼다.
    - 비트는 한 줄짜리다(`[•_•]⚙`).
    - 끝난 단계는 지금처럼 `✓ stage 04:10`으로 남긴다.

## 비목표

- main, TASKS, SKILLS, ACTIVITY 섹션의 모양 변경. AGENTS 섹션은 행 앞에 비트만 붙인다.
- 설정(캐릭터 끄기, 테마). 필요해지면 그때 추가한다.
- 상태와 reducer(`hooks/state.ts`) 변경. 화면에 쓸 정보는 이미 다 있다.
- mobile 화면을 위한 별도 작업. `Svg`가 있으니 데스크톱 경로가 그대로 쓰이면 충분하다.

## 안티골 (동작해도 실패로 본다)

- 데스크톱 애니메이션이 매 redraw(100ms ticker)마다 처음부터 다시 시작해서 끊겨 보이는 것.
- 터미널에서 캐릭터 때문에 줄이 패널 폭(`PANE_COLUMNS = 48`, 본문 `bodyColumns`)을 넘어 줄바꿈되거나 테두리가 깨지는 것.
- idle인데 캐릭터가 계속 움직이는 것.
- `prefers-reduced-motion`을 무시하는 것. 데스크톱 SVG CSS에 `@media (prefers-reduced-motion: reduce)`로 애니메이션을 끈다.

## 제약

- 렌더 API(`.claude-plugin/types/claude-code/index.d.ts`)
  - `Svg`는 desktop, vscode, mobile에만 있다. 터미널 표(`Elements['terminal']`)에는 없다. 그래서 `e.surface`로 갈라야 한다.
  - `SvgProps`는 `source`(131072자 이하)와 `alt`(필수)를 받고, `width`/`height`, `isInteractive`를 받을 수 있다.
  - `isInteractive`가 없으면 SVG를 이미지로 그린다. 이미지 SVG에서도 CSS keyframes는 대부분의 웹 엔진에서 돈다. savvy-progress가 이 방식을 쓴다. 실제 데스크톱 앱에서 확인해야 한다(아래 "빌더에게 남긴 것").
- 패널은 이미 busy일 때 `FRAME_MS = 100` 간격으로 `ui.render`를 다시 부른다(`hooks/register.tsx` ticker). 터미널 프레임은 여기에 얹는다. 시계를 새로 만들지 않는다.
- 데스크톱 SVG의 `source` 문자열은 프레임 번호와 무관해야 한다. 같은 상태라면 redraw마다 같은 문자열이어야 호스트가 이미지를 새로 만들지 않을 가능성이 높다. 경과 시간처럼 바뀌는 값은 SVG 밖의 `Text`에 둔다.
- 새 의존성은 들이지 않는다.

## Approaches

- **A. 화면별로 다르게 그린다 (선택).**
  - 데스크톱은 SVG를 한 번 만들고 움직임은 CSS keyframes에 맡긴다.
  - 터미널은 문자 캐릭터 프레임을 기존 100ms 시계로 바꾼다.
  - 상태와 reducer는 그대로 두고 view만 바뀐다. 목업 그대로 나온다.
  - 대가는 캐릭터 정의가 두 벌(픽셀 격자, 문자 프레임)이라는 점이다.
- B. 터미널도 `Raster` + `$.ui.blit`으로 반칸 블록(`▀`) 픽셀을 그린다.
  - 캐릭터 정의가 한 벌이면 되지만, 쓰지 않던 API를 들여야 한다.
  - 작은 칸에서는 형태가 뭉개지고, 승인된 터미널 목업과도 모양이 다르다.
- C. 데스크톱 SVG를 프레임마다 새로 만든다. 초당 10번 큰 문자열을 보내야 하고 깜빡일 위험이 있어 처음에 뺐다.

사용자가 A를 골랐다.

## 정해진 것

- 캐릭터 배치와 모양은 목업대로 한다.
  - 단계 캐릭터: Clawd 몸통 + 단계별 모자와 도구
  - 에이전트: 비트
- 화면별 표현은 Approach A로 한다.
- 작업 브랜치는 `feat/stage-characters`이다.
- 끝난 단계 아래의 에이전트는 지금처럼 남긴다.
- 비트는 상태 아이콘 자리를 대신하고, 상태별 표정은 위 표를 따른다(내 판단).

## 빌더에게 남긴 것

- **파일 구성.** 스프라이트 데이터와 그리는 함수는 새 파일(예: `hooks/characters.ts`)에 둔다.
  - SVG 문자열 생성: `stageSvg(stage, scale, on)`, `botSvg(role, scale, status)`
  - 터미널 프레임: `stageFrame(stage, f, on)`, `botFrame(role, f, status)` (status는 위 표의 5가지)
  - `view.tsx`의 `spPanel`, `agentRow`, `agentsPanel`이 이 함수들을 surface에 따라 부른다.
  - `UI`에 `Svg`가 있는지(`'Svg' in ui`)로 갈라도 되고, `e.surface`를 `Frame`에 실어 넘겨도 된다.
- **터미널 레이아웃.**
  - 캐릭터 블록 폭은 14칸 안팎이다(모자/몸 9칸 + 도구 3칸 + 간격 2칸). 오른쪽 내용은 그 나머지 폭에 맞춘다.
  - 폭이 너무 좁으면(예: 본문 30칸 미만) 캐릭터를 빼고 지금 줄로 돌아간다. 기준값은 빌더가 정한다.
- **터미널 프레임 속도.**
  - 목업은 도구를 3틱(300ms)마다, 다리를 5틱(500ms)마다 바꾼다. 같은 비율로 맞추면 된다.
  - 비트는 3틱마다 바꾼다.
- **데스크톱 애니메이션 확인.** 실제 데스크톱 앱에서 두 가지를 본다.
  - 이미지 SVG의 CSS keyframes가 도는지 본다.
  - 100ms redraw 때 처음부터 다시 시작하지 않는지 본다.
  - 둘 중 하나라도 안 되면 `isInteractive: true`로 바꿔서 다시 본다.
  - 그래도 끊기면 데스크톱에서만 ticker를 끄는 방안을 사용자에게 가져온다. 그 경우 스피너와 막대 shimmer도 데스크톱에서 멈추게 된다.
- **테스트.** 상태를 심을 수 없으니 export한 순수 함수만 단위 테스트한다.
  - `stageFrame`의 줄 수와 폭이 일정한지 본다.
  - `on=false`면 프레임이 바뀌지 않는지 본다.
  - `botFrame`이 상태 5가지마다 표의 글리프를 내는지 본다.
  - SVG에 `prefers-reduced-motion`이 들어 있는지 본다.
  - 같은 입력이면 SVG 문자열이 같은지 본다.
- **README.** SUPERPOWERS 설명에 캐릭터 한 줄을 넣는다. GIF와 스크린샷은 다시 찍는다. 찍는 방법은 기존 녹화 방식을 따른다.
- **버전.** 기존 관례대로 minor를 올린다(1.0.0 → 1.1.0).
